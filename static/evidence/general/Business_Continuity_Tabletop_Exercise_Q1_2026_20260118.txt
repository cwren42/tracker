EXERCISE SCENARIO
================================================================================

SCENARIO: Ransomware Attack - Critical Systems Encrypted

Date/Time: Friday, 3:00 PM (simulated)
Initial Detection: Help desk receives multiple calls about encrypted files

SCENARIO DETAILS:

At 3:00 PM on a Friday afternoon, the IT help desk begins receiving calls
from employees reporting that their files have been encrypted and they're
seeing ransom notes on their screens. Initial investigation reveals:

AFFECTED SYSTEMS:
• File server (\\FILESERVER\Shared) - All files encrypted
• 12 workstations - Files encrypted, ransom notes displayed
• SQL Server databases - Not encrypted (but offline as precaution)
• One Azure VM (WEB-PROD-02) - Encrypted and offline

NOT AFFECTED:
• Email/Microsoft 365 - Operational
• Primary web servers - Operational  
• Most workstations - Operational
• Network infrastructure - Operational
• Azure AD/identity systems - Operational

INITIAL INFORMATION:
• Ransom note demands $50,000 in Bitcoin within 72 hours
• Attackers threaten to publish data if not paid
• Unknown how attackers gained access
• Unknown if backups are affected
• Unknown extent of data exfiltration

INJECTS (Additional complications introduced during exercise):
1. News media contacts PR department asking about "data breach" (11:00 AM)
2. Customer calls asking if their data is safe (11:20 AM)
3. One backup server also appears compromised (11:45 AM)
4. Forensics reveals data exfiltration occurred 2 weeks ago (12:00 PM)

PHASE 1: DETECTION & INITIAL RESPONSE (10:30 - 11:15 AM)
--------------------------------------------------------------------------------

Discussion Topic: "Help desk receives encrypted file reports - what happens?"

PARTICIPANTS IDENTIFIED:

1. DETECTION & NOTIFICATION (First 15 minutes)
   ✓ Help desk receives initial reports at 3:00 PM
   ✓ Help desk escalates to IT Operations Manager (within 5 minutes)
   ✓ IT Ops Manager investigates and confirms ransomware (10 minutes)
   ✓ IT Ops Manager immediately notifies CISO
   ✓ CISO notifies CEO and executive team
   ✓ Decision: Declare disaster state (CEO authority)

   TIME TO DISASTER DECLARATION: ~30 minutes from first report

2. IMMEDIATE ACTIONS (First 30 minutes)
   ✓ Isolate affected systems from network (prevent spread)
   ✓ Take SQL Server offline as precaution (protect databases)
   ✓ Disable affected user accounts
   ✓ Block suspicious network traffic at firewall
   ✓ Preserve forensic evidence (logs, system images)
   ✓ Assess backup systems (verify backups not encrypted)

   TEAM PERFORMANCE: Good initial response procedures identified

3. COMMUNICATION TREE ACTIVATION (First hour)
   ✓ CISO initiates communication tree
   ✓ Executive team notified via mobile phones
   ✓ IT team assembled (all hands on deck)
   ✓ Emergency conference call line activated
   ✓ IT ticket created: INC-2026-001 "Ransomware Incident"

   DISCUSSION POINT: Should we tell employees immediately or wait
                     until we have more information?

   DECISION: Send immediate communication within 1 hour acknowledging
             incident and instructing employees not to touch encrypted
             systems. Detailed update within 4 hours.

4. LAW ENFORCEMENT NOTIFICATION
   ✓ CEO makes decision to contact FBI Cyber Division
   ✓ Legal counsel contacted regarding regulatory notifications
   ✓ Insurance provider contacted (cyber insurance policy)

   DISCUSSION: When to pay vs. recover from backups?
   CONSENSUS: Never pay ransom - recover from backups
              (FBI guidance, insurance advice, company policy)


PHASE 2: RECOVERY OPERATIONS (11:30 AM - 12:00 PM)
--------------------------------------------------------------------------------

Discussion Topic: "Initial assessment complete - begin recovery"

PARTICIPANTS IDENTIFIED:

1. BACKUP VERIFICATION (Hours 1-2)
   ✓ IT team verifies backup integrity
   ✓ Most recent file server backup: Last night (14 hours old)
   ✓ Most recent VM backup: This morning (6 hours old)
   ✓ Backups confirmed clean (not encrypted)
   ✓ Test restoration of sample files: Successful

   INJECT DISCUSSION: "One backup server appears compromised"
   TEAM RESPONSE: 
   - Isolate that backup server immediately
   - Verify other backup locations (Azure Backup confirmed clean)
   - Use Azure Backup for restoration (cloud backups unaffected)
   
   LEARNING: Multiple backup locations and offline backups critical

2. RESTORATION PRIORITIES (Hours 2-4)
   Team discussed priority order:
   
   Priority 1 (Immediate):
   ✓ Communication systems (Teams/Email) - Already working ✓
   ✓ Identity/authentication - Already working ✓
   
   Priority 2 (0-4 hours):
   ✓ File server restoration (most critical shared files)
   ✓ Encrypted Azure VM rebuild
   ✓ Workstation reimaging (12 affected machines)
   
   Priority 3 (4-8 hours):
   ✓ SQL Server back online (was not encrypted)
   ✓ Full file server restoration complete
   ✓ All workstations restored
   
   ESTIMATED FULL RECOVERY TIME: 8-12 hours

3. FORENSICS & SECURITY (Ongoing)
   ✓ Security team investigates attack vector
   ✓ Review firewall logs, endpoint logs, email logs
   ✓ Identify initial compromise method
   ✓ Determine extent of data exfiltration

   INJECT DISCUSSION: "Forensics shows data exfiltration 2 weeks ago"
   TEAM RESPONSE:
   - This triggers data breach notification requirements
   - Legal counsel guides notification process
   - HR Director prepares employee notification
   - VP Sales prepares customer notification
   - CEO prepares stakeholder communication
   
   LEARNING: Must have breach notification procedures ready

4. CUSTOMER COMMUNICATION (Hours 2-6)
   VP Sales/Marketing discussed approach:
   
   Hour 2: Internal communication to sales team
           "Do not promise customers anything yet"
   
   Hour 4: Website status page updated
           "Experiencing technical issues, working on resolution"

           "Brief service disruption, data being investigated,
            will provide updates every 6 hours"

   INJECT DISCUSSION: "News media contacts PR"
   TEAM RESPONSE:
   - CEO designated as sole media spokesperson
   - PR department prepared statements
   - "We are aware of an incident and investigating"
   - Directed to await formal company statement
   
   LEARNING: Need media communication templates ready

5. ALTERNATE WORK ARRANGEMENTS (Hours 0-24)
   Operations team discussed employee work:
   
   ✓ Employees without encrypted systems: Continue working
   ✓ Employees with encrypted systems: Temporary machines or WFH
   ✓ IT team: Extended hours for recovery (bring in food)
   ✓ Monday plan: Most operations resumed, some manual processes
   
   COO discussed space/logistics:
   ✓ Conference rooms available for temporary workspace
   ✓ Spare laptops available (inventory: 8 machines)
   ✓ More laptops ordered for Monday delivery
   ✓ VPN capacity sufficient for increased remote work

6. DO NOT PAY RANSOM
   Executive team unanimous decision:
   
   ✓ Company policy: Do not pay ransom (ever)
   ✓ FBI recommendation: Do not pay (funds terrorism)
   ✓ No guarantee attacker will decrypt files
   ✓ We have clean backups - can recover
   ✓ Insurance covers recovery costs (not ransom)
   
   DECISION: Proceed with backup restoration, do not contact attackers


PHASE 3: RETURN TO NORMAL & LESSONS LEARNED (12:00 - 12:20 PM)
--------------------------------------------------------------------------------

Discussion Topic: "Recovery progressing - when can we call it done?"

PARTICIPANTS IDENTIFIED:

1. RETURN TO NORMAL CRITERIA
   Team discussed what "success" looks like:
   
   ✓ All critical systems operational
   ✓ All employees able to perform job functions
   ✓ Customer-facing services restored
   ✓ Data integrity verified
   ✓ Security controls reinforced (prevent reinfection)
   ✓ Forensics complete (understand what happened)
   ✓ Notifications complete (regulatory, customers, employees)
   
   ESTIMATED TIME TO "ALL CLEAR": 5-7 days
   - Technical recovery: 8-12 hours
   - Forensics completion: 3-5 days
   - Verification and monitoring: Ongoing

2. POST-INCIDENT ACTIVITIES
   ✓ Post-mortem meeting (1 week after)
   ✓ Root cause analysis
   ✓ Update security controls
   ✓ Update incident response procedures
   ✓ Employee training on phishing/security
   ✓ Insurance claim submission
   ✓ Board notification and report

3. LESSONS LEARNED (Discussed)
   
   What Worked Well:
   ✓ Team knew their roles and responsibilities
   ✓ Communication tree worked effectively
   ✓ Backup systems were adequate and accessible
   ✓ Executive decision-making was clear and rapid
   ✓ Customer communication approach was good
   
   What Needs Improvement:
   ⚠ Need faster way to image multiple workstations simultaneously
   ⚠ Need pre-written breach notification templates
   ⚠ Need more spare laptops on hand (only 8 available)
   ⚠ Need media communication templates ready
   ⚠ Consider MFA on file server access (prevent lateral movement)
   ⚠ Need automated forensics tools (faster investigation)
   
   Gap Identified: Backup server was on same network as production
   CRITICAL ISSUE: If attacker had more time, could have destroyed
                   all backups. Need truly offline/immutable backups.

4. Leadership ✓
   - Executive team engaged and decisive
   - Clear chain of command established
   - Risk tolerance well understood (no ransom payment)
   - Strong support for IT recovery efforts

WEAKNESSES IDENTIFIED:

1. Backup Security ⚠
   ISSUE: Backup server on same network as production systems
   RISK: Attacker could potentially destroy backups
   RECOMMENDATION: Implement immutable/offline backups (Azure Backup
                   with immutable vaults or tape backup offsite)
   PRIORITY: HIGH
   OWNER: Chris Wren (IT Manager)
   DUE DATE: March 31, 2026

2. Mass Workstation Imaging ⚠
   ISSUE: Reimaging 12 workstations would take significant time
          (8-10 hours for all machines)
   RISK: Extended user downtime
   RECOMMENDATION: Implement automated deployment solution (MDT/SCCM
                   or Intune Autopilot) for faster recovery
   PRIORITY: MEDIUM
   OWNER: IT Operations Manager
   DUE DATE: June 30, 2026

3. Breach Notification Templates ⚠
   ISSUE: No pre-written customer/employee notification templates
   RISK: Delayed notifications, inconsistent messaging
   RECOMMENDATION: Create templates for various breach scenarios,
                   pre-approved by legal counsel
   PRIORITY: HIGH
   OWNER: VP Sales/Marketing + Legal
   DUE DATE: February 28, 2026

4. Media Response Procedures ⚠
   ISSUE: No formal media response procedures
   RISK: Inconsistent messaging, PR problems
   RECOMMENDATION: Develop media communication plan and train
                   spokesperson
   PRIORITY: MEDIUM
   OWNER: CEO + PR Consultant
   DUE DATE: April 30, 2026

5. Spare Equipment Inventory ⚠
   ISSUE: Only 8 spare laptops available (83 employees)
   RISK: Cannot quickly replace multiple failed systems
   RECOMMENDATION: Maintain spare equipment inventory (10% of fleet,
                   ~8-10 laptops)
   PRIORITY: LOW (current inventory adequate for most scenarios)
   OWNER: Operations Manager
   DUE DATE: Maintain as budget allows

6. Multi-Factor Authentication on File Servers ⚠
   ISSUE: File server access doesn't require MFA
   RISK: Lateral movement after initial compromise
   RECOMMENDATION: Implement MFA for file server access, especially
                   for privileged accounts
   PRIORITY: HIGH
   OWNER: Chris Wren (IT Manager)
   DUE DATE: March 31, 2026
