SECTION 1: INCIDENT DEFINITION & CLASSIFICATION
================================================================================

1.1 WHAT IS A SECURITY INCIDENT?
---------------------------------
A security incident is any event that compromises the confidentiality,
integrity, or availability of information systems, data, or physical assets.

Examples of Security Incidents:
✓ Unauthorized access to systems or data
✓ Malware infections (ransomware, viruses, trojans)
✓ Phishing attacks (successful or attempted)
✓ Data breach or data loss
✓ Denial of Service (DoS) attacks
✓ Lost or stolen devices (laptops, phones, tablets)
✓ Unauthorized disclosure of confidential information
✓ Insider threats or malicious employee activity
✓ Physical security breaches (facility access, theft)
✓ Social engineering attacks
✓ Compromised user accounts
✓ Website defacement
✓ Vulnerability exploits
✓ Third-party vendor security incidents affecting Cirque

What is NOT an Incident (but should still be reported):
- Suspicious emails (report to IT for analysis)
- Failed login attempts (system alerts IT automatically)
- Spam or junk mail
- System errors or outages (not security-related)
- Lost passwords (help desk request)


1.2 INCIDENT SEVERITY CLASSIFICATION
-------------------------------------

SEVERITY 1 - CRITICAL (Response Time: Immediate)
- Active ransomware attack or major malware outbreak
- Confirmed data breach with customer/employee PII exposed
- Complete system or network outage due to security incident
- Ongoing active attack or intrusion
- Loss of critical business systems
- Media attention or public disclosure imminent
- Regulatory reporting required (GDPR, CCPA, etc.)
→ ACTION: Activate full Incident Response Team immediately
→ NOTIFICATION: CTO, CEO, Legal within 1 hour

SEVERITY 2 - HIGH (Response Time: Within 2 hours)
- Suspected data breach (investigation needed)
- Compromised privileged account
- Malware on multiple systems
- Successful phishing attack with credential theft
- Lost/stolen device with unencrypted data
- DDoS attack affecting availability
- Insider threat detected
→ ACTION: Activate core Incident Response Team
→ NOTIFICATION: CTO, IT Manager immediately

SEVERITY 3 - MEDIUM (Response Time: Within 24 hours)
- Isolated malware infection (single device)
- Attempted unauthorized access (blocked)
- Lost/stolen device with encrypted data
- Minor data leak (limited scope)
- Suspicious network activity under investigation
- Failed phishing attempt (user reported)
→ ACTION: IT Security investigates
→ NOTIFICATION: IT Manager within 4 hours

SEVERITY 4 - LOW (Response Time: Within 3 days)
- Spam or phishing emails (not clicked)
- Minor policy violations
- Unsuccessful attack attempts
- Security awareness incidents (user mistakes)
→ ACTION: IT logs and tracks for trending
→ NOTIFICATION: Weekly summary to IT Manager


1.3 INCIDENT CATEGORIES
------------------------

3.4 INITIAL ASSESSMENT & INVESTIGATION
---------------------------------------
Performed by: IT Security (Amanda Foster) or IT Manager (Chris Wren)
Timeline: Within response time based on severity

Investigation Steps:
1. Verify the incident is legitimate (not false positive)
2. Determine scope and impact:
   - What systems are affected?
   - What data is involved?
   - How many users impacted?
   - Is attack ongoing or contained?
   - Is this part of larger campaign?
3. Classify severity (may upgrade/downgrade from initial report)
4. Gather forensic evidence:
   - System logs
   - Network traffic captures
   - Email headers
   - Screenshots
   - Witness statements
5. Document timeline of events
6. Preserve evidence (don't alter affected systems)
7. Determine if law enforcement notification needed

Investigation Findings Documented in Incident Ticket

PHASE 3: CONTAINMENT, ERADICATION & RECOVERY
================================================================================

4.1 CONTAINMENT STRATEGY
-------------------------
Goal: Stop the incident from spreading while preserving evidence

SHORT-TERM CONTAINMENT (Immediate Actions):
✓ Isolate affected systems (disconnect from network, don't power off)
✓ Disable compromised user accounts
✓ Block malicious IPs/domains at firewall
✓ Quarantine malicious emails
✓ Change passwords for compromised accounts
✓ Enable additional monitoring/logging
✓ Take systems offline if actively under attack

Containment Actions Based on Incident Type:

MALWARE/RANSOMWARE:
→ Disconnect infected devices from network (leave powered on)
→ Block command & control (C2) IPs at firewall
→ Stop file server sync/replication
→ Verify backups are clean and accessible
→ Do NOT pay ransom (FBI guidance + company policy)

PHISHING/ACCOUNT COMPROMISE:
→ Disable affected user accounts immediately
→ Force password reset on compromised accounts
→ Revoke all active sessions/tokens
→ Review account activity logs
→ Check for unauthorized email forwards/rules
→ Scan for data exfiltration

DATA BREACH:
→ Identify what data was accessed/exfiltrated
→ Stop ongoing access (close entry point)
→ Preserve logs and evidence
→ Determine if notification required (GDPR, CCPA)
→ Consult with Legal team

LOST/STOLEN DEVICE:
→ Remote wipe device immediately (if enabled)
→ Disable device in MDM (Intune)
→ Revoke device certificates
→ Force password reset for user
→ Review data stored locally vs. cloud
→ File police report (if stolen)

DENIAL OF SERVICE:
→ Engage DDoS mitigation service
→ Block attack sources at firewall
→ Increase bandwidth if possible
→ Notify Azure support
→ Consider moving to alternative IP range


4.2 LONG-TERM CONTAINMENT
--------------------------
Implement temporary fixes to allow systems to resume operation:
✓ Apply emergency patches
✓ Implement additional firewall rules
✓ Deploy compensating controls
✓ Monitor affected systems continuously
✓ Backup system state for forensics


4.3 ERADICATION
----------------
Goal: Remove the threat and close security gaps

Actions:
✓ Remove malware from all affected systems
✓ Delete malicious files and registry entries
✓ Close exploited vulnerabilities (patch systems)
✓ Remove unauthorized accounts or access
✓ Update security controls (firewall rules, AV signatures)
✓ Rebuild compromised systems from known-good backups (if needed)
✓ Verify threat is completely removed

Verification:
- Re-scan systems with multiple tools
- Review logs for residual activity
- Monitor for 72 hours minimum

Eradication Complete When:
→ No signs of malicious activity
→ All vulnerabilities patched
→ Systems scanned clean by multiple tools
→ Monitoring shows normal behavior


4.4 RECOVERY
-------------
Goal: Restore systems to normal operation and verify security

Recovery Steps:
1. Restore systems from clean backups (if rebuilt)
2. Re-apply security configurations
3. Change all passwords associated with incident
4. Test system functionality
5. Verify data integrity
6. Restore network connectivity (in phases)
7. Monitor intensively for 7-14 days
8. Verify backups are current

Validation:
✓ System performance normal
✓ No signs of compromise
✓ Security controls functioning
✓ Users able to access required resources
✓ Data integrity verified

Return to Production Approved By: IT Manager + CTO

SECTION 5: INCIDENT RESPONSE PLAYBOOKS
================================================================================

8.1 RANSOMWARE INCIDENT PLAYBOOK
---------------------------------
1. CONTAIN:
   - Disconnect infected systems from network (leave powered on)
   - Identify ransomware variant (search ransom note text)
   - Block C2 IPs at firewall
   - Stop replication/sync services
2. ASSESS:
   - How many systems encrypted?
   - What data is affected?
   - Are backups accessible and clean?
   - Ransom amount and payment deadline
3. DO NOT PAY RANSOM (company policy + FBI guidance)
4. RECOVER:
   - Restore from clean backups
   - Check NoMoreRansom.org for decryption tools
   - Rebuild systems from scratch if needed
5. PREVENT:
   - Identify entry point (phishing, remote access, vulnerability)
   - Patch vulnerabilities
   - Enhance email filtering
   - Implement application whitelisting

8.2 PHISHING INCIDENT PLAYBOOK
-------------------------------
1. User reports suspicious email to security@cirque.com
2. User forwards email (do not click links or attachments)
3. IT Security analyzes email headers and links
4. If malicious:
   - Quarantine email from all mailboxes
   - Block sender domain
   - Check if anyone clicked link or opened attachment
   - If credentials entered: Force password reset, disable account, check for unauthorized access
   - If attachment opened: Scan device for malware, isolate if infected
5. Send warning email to all employees (if widespread phishing campaign)
6. Update email filtering rules

8.3 DATA BREACH PLAYBOOK
-------------------------
1. IDENTIFY:
   - What data was accessed/exfiltrated?
   - How was data accessed? (hacked, lost device, insider, misconfiguration)
   - When did breach occur? (time window)
   - Who is affected? (customers, employees, count)
2. CONTAIN:
   - Stop ongoing access
   - Secure entry point
   - Preserve evidence
3. LEGAL NOTIFICATION:
   - Consult Legal team immediately
   - Determine if PII, PHI, or financial data involved
   - Regulatory notification requirements (GDPR 72 hours)
   - Customer notification requirements
4. COMMUNICATION:
   - Prepare notification letters
   - Offer credit monitoring (if PII)
   - Set up call center for inquiries
5. REMEDIATE:
   - Fix vulnerability
   - Enhance monitoring
   - Implement additional controls

8.4 LOST/STOLEN DEVICE PLAYBOOK
--------------------------------
1. User reports device lost/stolen to IT immediately
2. Determine:
   - Device type and ownership (company vs. BYOD)
   - Was device encrypted? (BitLocker, FileVault)
   - What data was stored locally?
   - Was device PIN/password protected?
   - When was it last seen?
3. IMMEDIATE ACTIONS:
   - Remote wipe device (Intune MDM)
   - Disable device in MDM
   - Revoke device certificates
   - Disable user account temporarily
   - Check for recent sign-ins from unusual locations
4. If stolen: File police report
5. Recovery: If device found, verify not compromised before re-enrolling
6. ASSESS RISK:
   - Low: Encrypted device, no local data, remote wiped
   - High: Unencrypted device with local PII/confidential data
   - Determine if data breach notification required
