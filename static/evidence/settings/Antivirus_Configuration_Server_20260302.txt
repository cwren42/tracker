ANTIVIRUS CONFIGURATION BY PLATFORM
================================================================================

LINUX SERVERS/INSTANCES (Ubuntu Server, CentOS, RHEL, Amazon Linux)
--------------------------------------------------------------------------------
Required: NO - Antivirus is not required for Linux servers

Rationale:
- Relatively few viruses target Linux server environments
- Linux architecture provides strong inherent security
- Permission-based system and security modules (SELinux/AppArmor) limit risk
- Server workloads typically don't involve user file downloads/execution
- Attack surface minimized through server hardening practices
- Regular security patching provides adequate protection

Security Measures Implemented Instead:
✓ Operating system hardening (CIS benchmarks applied)
✓ Automatic security updates enabled
✓ Host-based intrusion detection (OSSEC/Wazuh)
✓ File integrity monitoring (AIDE/Tripwire)
✓ Centralized logging and monitoring
✓ Network security groups and firewall rules
✓ Minimal package installation (reduced attack surface)
✓ Regular vulnerability scanning
✓ Security patch management (automated)

Linux Server Security Stack:
- Firewall: iptables/nftables/UFW
- IDS/IPS: OSSEC, Wazuh, or Snort
- File Integrity: AIDE (Advanced Intrusion Detection Environment)
- Log Management: rsyslog with centralized SIEM
- Vulnerability Scanning: OpenVAS, Nessus
- Configuration Management: Ansible/Salt/Puppet
- Patch Management: Automated via yum-cron/unattended-upgrades

Monitoring:
- Security log monitoring 24/7
- Automated alerts for suspicious activity
- Vulnerability scans run weekly
- Security patches applied within 7 days (critical), 30 days (other)
- Configuration drift detection
- Performance monitoring (unusual patterns may indicate compromise)

Compliance Notes:
✓ This configuration is acceptable for SOC 2 compliance
✓ Many auditors and security frameworks recognize Linux servers as low-risk
✓ Alternative security controls provide equivalent or superior protection
✓ If only running Linux servers, Antivirus evidence item can be deactivated

Evidence Item Status:
- If running ONLY Linux servers: Consider deactivating this evidence item
- Our environment includes Windows servers, so evidence item remains ACTIVE
- Linux servers documented for completeness


WINDOWS SERVERS/INSTANCES (Windows Server 2016/2019/2022)
--------------------------------------------------------------------------------
Required: YES - Antivirus protection is MANDATORY for all Windows servers

Solution: Windows Defender (Native)
- Microsoft Windows Defender Antivirus is the approved solution
- Built into Windows Server operating systems
- Sufficient for enterprise server protection when properly configured
- No additional third-party antivirus required
- Optimized for server workloads with minimal performance impact

Configuration Requirements:
✓ Real-time protection: ENABLED
✓ Cloud-delivered protection: ENABLED
✓ Automatic sample submission: ENABLED
✓ Network protection: ENABLED
✓ Controlled folder access: ENABLED (for critical data directories)
✓ Automatic definition updates: ENABLED (multiple times daily)
✓ Scan schedule: Weekly (during maintenance window)
✓ Exclusions: Only approved application directories (databases, logs)

Windows Defender Server Features Enabled:
- Virus & threat protection
- Real-time scanning of file system
- Network traffic inspection
- Behavior monitoring
- Script scanning
- Email scanning (if applicable)
- Boot sector protection

Server-Specific Configurations:
- Exclusions configured for performance-critical applications:
  * SQL Server database files (.mdf, .ldf) and directories
  * IIS log directories
  * Application-specific working directories
  * Backup staging directories (scanned separately)
- Scheduled scans during low-usage periods (2:00 AM - 5:00 AM)
- Resource throttling enabled to prevent performance impact
- Real-time protection takes precedence over scheduled scans

Management:
- Managed through Microsoft Intune/Endpoint Manager
- Centralized monitoring via Microsoft 365 Security Center
- Automatic updates via Windows Server Update Services (WSUS)
- Security alerts aggregated and monitored by SOC
- Policy enforcement through Group Policy Objects (GPO)

Performance Considerations:
- CPU usage throttling configured (max 20% during business hours)
- Scan schedule aligned with maintenance windows
- Exclusions reviewed and approved by security team
- Performance baselines monitored continuously
- Application-specific tuning documented

Compliance:
✓ All Windows servers have Defender enabled
✓ Regular compliance scans verify coverage
✓ Non-compliant servers flagged and remediated within 24 hours
✓ Administrators cannot permanently disable protection without CISO approval
✓ Tamper protection prevents unauthorized configuration changes

================================================================================
BACKUP AND DISASTER RECOVERY
================================================================================

Backup Scanning:
- All backup data scanned before archival
- Backup staging directories excluded from real-time scanning
- Post-backup antivirus scan scheduled automatically
- Ensures clean backups and clean restores
- Malware detected in backups triggers investigation

Recovery Procedures:
- Server restoration from clean, verified backups
- Antivirus definitions updated before restoration
- Full scan performed post-restoration
- Security team validates clean state before production
- Root cause analysis performed for malware incidents


================================================================================
INCIDENT RESPONSE
================================================================================

Malware Detection Procedure:
1. Automatic alert generated by Windows Defender or OSSEC
2. Security Operations Center (SOC) notified immediately
3. Affected server isolated from network if critical
4. Threat analysis performed (scope, impact, origin)
5. Malware removed or server reimaged
6. Root cause investigated
7. Additional protections implemented if needed
8. Incident documented and reported to management
9. Post-incident review conducted

Escalation Path:
- Level 1: SOC/IT Operations (initial response)
- Level 2: IT Security Team (investigation and remediation)
- Level 3: CISO (significant incidents, data breach potential)
- Executive Management (business-critical systems, data breach)

Server-Specific Considerations:
- Production servers: Immediate escalation to CISO
- Database servers: DBA and security team coordinate
- Web servers: Load balancer failover during remediation
- Critical infrastructure: Business continuity plan activated
