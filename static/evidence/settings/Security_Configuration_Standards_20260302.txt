Purpose:
--------
This document defines the baseline security configuration standards for all
Cirque Corporation IT systems. These standards are maintained by the IT team
and applied to all systems to ensure consistent security posture. Standards
are reviewed annually or when business needs change.

Scope:
------
This baseline applies to:
- All production servers (Windows Server, Linux)
- All employee workstations (Windows, macOS, Linux)
- All mobile devices (Android, iOS)
- All network security devices (firewalls, VPN)
- All cloud infrastructure (Azure VMs, Azure services)
- All security tools and monitoring systems

Configuration standards are based on Center for Internet Security (CIS)
benchmarks and industry best practices, customized for Cirque's environment.

2.1 USER AUTHENTICATION & ACCESS CONTROL
-----------------------------------------
✓ Password Policy (via PAM):
  - Minimum length: 14 characters
  - Complexity: minlen=14 dcredit=-1 ucredit=-1 ocredit=-1 lcredit=-1
  - Password history: 24 passwords remembered (remember=24)
  - Maximum age: 90 days
  - Minimum age: 1 day
  - Warning: 7 days before expiration
  - Inactive period: 30 days
  - Account lockout: 5 failed attempts, 30 minute lockout (faillock)

✓ SSH Access:
  - SSH Protocol 2 only (Protocol 1 disabled)
  - Root login: DISABLED (PermitRootLogin no)
  - Password authentication: DISABLED (PasswordAuthentication no)
  - Public key authentication: ENABLED (authorized_keys only)
  - Empty passwords: NOT PERMITTED (PermitEmptyPasswords no)
  - X11 forwarding: DISABLED (X11Forwarding no)
  - Max auth tries: 3
  - Login grace time: 30 seconds
  - Client alive interval: 300 seconds (5 minutes)
  - Client alive count max: 2
  - SSH keys: Ed25519 or RSA 4096-bit minimum
  - Allowed users: Specific named accounts only (AllowUsers directive)

✓ Sudo Configuration:
  - Sudo restricted to specific users in 'sudo' group
  - Sudo requires password re-authentication every 15 minutes
  - Sudo logs all commands to /var/log/sudo.log
  - Using sudoers.d for role-based access (no direct /etc/sudoers edits)

✓ User Accounts:
  - No shared accounts (individual accounts per person)
  - Service accounts have /sbin/nologin shell
  - Unused accounts disabled after 30 days
  - UID 0 only for root account

2.2 SYSTEM HARDENING
--------------------
✓ Kernel Parameters (sysctl):
  - IP forwarding disabled: net.ipv4.ip_forward=0 (unless router)
  - Send redirects disabled: net.ipv4.conf.all.send_redirects=0
  - Accept source routing disabled: net.ipv4.conf.all.accept_source_route=0
  - Accept ICMP redirects disabled: net.ipv4.conf.all.accept_redirects=0
  - Secure ICMP redirects disabled: net.ipv4.conf.all.secure_redirects=0
  - Log martians: net.ipv4.conf.all.log_martians=1
  - Ignore broadcast requests: net.ipv4.icmp_echo_ignore_broadcasts=1
  - Bad error message protection: net.ipv4.icmp_ignore_bogus_error_responses=1
  - Reverse path filtering: net.ipv4.conf.all.rp_filter=1
  - TCP SYN cookies: net.ipv4.tcp_syncookies=1
  - IPv6 disabled (if not used): net.ipv6.conf.all.disable_ipv6=1

✓ Filesystem Security:
  - Separate partitions: /tmp, /var, /var/log, /var/tmp, /home
  - /tmp mounted with noexec,nodev,nosuid
  - /var/tmp mounted with noexec,nodev,nosuid  
  - /dev/shm mounted with noexec,nodev,nosuid
  - Sticky bit set on world-writable directories
  - SUID/SGID binaries reviewed and minimized
  - Unused filesystems disabled: cramfs, freevxfs, jffs2, hfs, hfsplus, udf

✓ Boot Security:
  - GRUB bootloader password protected
  - Single user mode requires root password
  - Boot partition mounted read-only after boot

✓ UFW (Uncomplicated Firewall): ENABLED
✓ Default policy: Deny incoming, allow outgoing
✓ Allowed services:

  - Application-specific ports: Restricted to specific source IPs
✓ Rate limiting enabled on SSH (limit 10 connections per 30 seconds)
✓ Logging: Full logging enabled to /var/log/ufw.log
